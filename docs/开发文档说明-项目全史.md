### 为什么会有这两份

开发过程中有一个反复出现的教训：**代码里只能看到「现在是什么样」，看不到「为什么不是另一副样子」**。

比如 `utils/Theme.ets` 里那个 `#12706B`（深墨青）—— 它为什么不是网页版那个亮青绿 `#3AC8C2`？代码里没有答案，只有这一份文档里记着：那是为了让**白字**在填充色上达到 4.5:1 对比度（AGC 的硬指标），而你明确说过「不能用黑色字，很难看」。

再比如 `views/TasksView.ets` 里那一长串 `ForEach` 的 key 都带了一个 `-${this.tick}` 后缀 —— 看起来像冗余代码，其实是修一个**「保存后界面不刷新」**的 bug 加的：ArkUI V1 里 `ForEach` 的 key 不变就会复用旧节点，不重建。

这些「为什么」如果只留在聊天记录里，等过三个月就找不回来了。所以本文档的核心任务就是：**把对话里所有有决策价值的部分固化成文字**。

## 第 0 章 · 一页看懂这个项目

### 0.1 它是什么

**小记**（英文副标 XIAOJI）是一个**纯离线**的鸿蒙个人工作台 App。

它把「个人工作台」网页版的全部能力搬到了鸿蒙手机上，并且做了两件网页版做不到的事：

1. **数据全部存在本机**，装在手机上就能用，没有服务器、没有账号、没有网络请求
2. **一个系统权限都不申请**（不联网、不读设备标识、不在后台运行、不发系统通知）

### 0.5 三条最重要的经验

**① ArkUI V1 的「精准更新」是这个项目最大的性能与正确性陷阱。**

只有「属性表达式里直接读过 state 变量」的节点才会重画。**在方法调用里读 state 不算依赖**：

```typescript
// ❌ 这个数字永远不会变，切页才重建
Text(`${this.byStatus('todo').length} 件`)

// ✅ 必须把派生值预计算进 @State
@State gTodo: number = 0;
```

这个坑在 v4.2、v4.5 各被撞了一次，v4.5 之后全项目统一改成「派生值预计算进 `@State`」的模式。

**② 百分比高度会向上冒泡。**

`height('100%')` 在一个「高度由内容决定」的容器里，不会相对于兄弟元素，而是**冒泡到最近一个有确定高度的祖先**。结果就是子元素被拉到视口高。`GridRow`/`GridCol` 也救不了。解法只有一条：`onAreaChange` 量出高度，再回填一个**具体的数字**。

**③ 华为 AGC 的 UX 测试比人眼严。**

「正文对比度 > 4.5:1」这条在文档里标的是**「推荐」**，但 AGC 实测会把它计入「不通过」。我们 v4.20 的 App 里有 **183 处**文字色不达标 —— 人眼看完全正常，是脚本算出来的。

## 第 1 章 · 缘起与目标演进

### 1.1 起点：有个网页版叫「个人工作台」

项目不是凭空来的。`/Users/hina/Documents/deepseek-harness/个人工作台` 是一个已经能跑的 Next.js 15 + `node:sqlite` 网页版个人工作台，端口 3100，线上有 `https://workbench.lbuding.com`。

它的技术栈（这次全程只读参考，**任何改动都没落在它上面**）：

| 项 | 值 |
|---|---|
| 框架 | Next.js 15 |
| 存储 | `node:sqlite` |
| 本地端口 | 3100 |
| 线上 | `https://workbench.lbuding.com`（Tunnel → NAS `192.168.1.197:3100`） |
| 健康检查 | `GET /api/health` 免登录，返回 `{ok, sha, built, at}` |
| 登录态 | cookie `wb_session`，有效期 24h |
| 页面组件 | `components/` 下有 `Dashboard.tsx`（总览）、`TasksPage.tsx`（任务）、`Sidebar.tsx`、`Confirm.tsx`、`ReminderBell.tsx` 等 |
| 样式 | `app/globals.css`，CSS 变量定义设计 token |

一开始的诉求很朴素：**这是个网页，我想在鸿蒙手机上也能用。**

### 1.2 第一次转向：从「华为鸿蒙」到「纯 OpenHarmony 7.0」

最初的方案（v1.1）按「HarmonyOS NEXT，能用 HMS 就用 HMS」来设计，网络层用的是 **`@kit.RemoteCommunicationKit`（RCP）**。

到了 2026-11-06 前后，你改了口：

> 「我的手机是 OpenHarmony 7.0…我会自己安装进系统」[m00961]

这句话直接推翻了一整套技术选型。我去 SDK 里查证，结论是硬事实：

- `@kit.RemoteCommunicationKit.d.ts` 标注 `@since 4.1.0(11)`，但它**只存在于 `hms/` 目录**下
- `openharmony/` 目录里 grep `RemoteCommunication` **零命中**
- 连带 `librcp_c.so`、`SystemCapability.Collaboration.RemoteCommunication` 也全在 `hms/`

**结论：纯 OpenHarmony 上不能用 RCP，网络层只能用 `@ohos.net.http`。**

RCP 唯一的优势是能发 `PATCH` 方法。换回 http 后，`http.RequestMethod.PATCH` 标着 `@since 26.0.0`，所以有三种绕法：

| 方案 | 做法 | 结论 |
|---|---|---|
| **A** | 锁 `compatibleSdkVersion` 到 API 26 | 能用但放弃 API 24 兼容 |
| **B** | `const PATCH: http.RequestMethod = 'PATCH' as http.RequestMethod;` | ✅ **采用**（字符串强转，不锁兼容下限） |
| C | 让工作台加一个 POST 别名 | 改参照工程，违反只读约束 |

采用 B。这个方案在 v2.0 文档里就定下来了，**直到 v4.0 纯离线化后彻底不需要网络层，这个问题自动消失**。

### 1.3 第二次转向：从「联网版」到「纯离线版」

这是本项目**最大的架构转折**。

在 v2.x 时代，App 的形态是「鸿蒙壳 + 电脑上跑的工作台服务器」：

```
鸿蒙 App ──HTTP──> 你电脑上的 pnpm dev (3100) ──> node:sqlite
```

你当时接受了这个形态（原话是「我会自己安装进系统」），并配合做了：

- **测试模式自动登录**（v2.4）：因为工作台所有数据 API 都先 `requireAuth()`，没有任何免密开关，纯免登录会全 401。所以做的是「测试模式自动登录」，本地库 `auth_hash` 重置过
- **手机连电脑的局域网扫描**（v2.4）：`api/Http.ets` 的 `candidates()` 补 Mac 局域网 IP + mDNS 名、`scanLanForWorkbench()` 扫 /24、`localIPv4()` 用 `connection.getAllNetsSync()` 只认 wlan/wifi/eth

然后到了 v4.0，你提了这条：

> 「数据全存手机、离线可用」[m13184]

这一句话把整个网络层拆了。v4.0 的落盘范围：

**新增（4 个文件）**

| 文件 | 行数 | 职责 |
|---|---|---|
| `db/Db.ets` | 400 | relationalStore 封装、9 表 6 索引、事务、静态 `now()` |
| `db/Repo.ets` | 1,690 | 把对象翻译成 SQL，方法名/返回结构与原 HTTP 接口一一对应 |
| `db/Boot.ets` | 62 | `Boot.start(ctx)` / `Boot.when()` 开库闸门 |
| `db/LocalAI.ets` | 287 | 离线规则拆任务 / 复盘草稿 |

**删除**

- `pages/Index.ets` 删掉登录门、服务器地址输入、健康检查、TestMode 自动登录、logout
- `views/SettingsView.ets` 整页重写（本地数据 / 备份与恢复 / 称呼 / 通知与提醒 / 清空数据 / 关于）
- 联网层 `api/Http.ets` / `api/Endpoints.ets` / `utils/TestMode.ets` **归档到工程根 `legacy-server-client/`**（移出编译图，留作历史）

**权限回收**

- `module.json5` 撤掉 `ohos.permission.INTERNET` 与 `GET_NETWORK_INFO`，只留 `PUBLISH_AGENT_REMINDER`

**关键设计决策：`Repo` 的方法签名与原 HTTP 接口一一对应。**

这不是巧合，是刻意的：让 `store/Store.ets` 里 22 处 `Http` 调用换成 `Repo` 调用时，**视图层几乎一行没改**。这让 v4.0 这个大改造的风险可控 —— 如果当时同时改了数据层的接口形状，整个 UI 层都要跟着返工。

### 1.4 第三次转向：从「零权限申请」到「零权限」

v4.7 做上架改造时，App 声明了唯一一个权限：

```json5
"requestPermissions": [
  { "name": "ohos.permission.PUBLISH_AGENT_REMINDER" }
]
```

用它做**系统代理提醒**（`utils/Remind.ets`，252 行）—— 到点弹一条系统通知，类似网页版的浏览器 Notification。

但 AGC 上架时，「受限 ACL 权限（HarmonyOS API9 及以上）」那一栏需要单独申请、单独审核。这件事在 v4.8–v4.19 期间一直悬着：profile 的 `permissions` 是空的、`acls.allowed-acls` 是空的，所以提醒一直不工作。

排查过程记录在 v4.14（文档 §13.4）：

```
reschedule: candidates=0     ← 库里没有符合条件的任务，不是代码问题
W C01203/foundation/Ans: ReminderControl com.lbuding.workbench, notification not allowed.
1700002 The number of reminders exceeds the limit   ← 误导式报错
```

`1700002` 是**误导**的，真实原因是包不被允许发通知。

最后你在 v4.20 拍了板：

> 「你帮我把这个软件需要系统提示的那个部分取消了吧，我不请求任何系统权限了」[m26154]

v4.20 的落盘：

- `module.json5` **删掉整段 `requestPermissions`** ⇒ 编译产物里连 `reqPermissions` 字段都不存在
- **整文件删除** `entry/src/main/ets/utils/Remind.ets`
- `pages/Index.ets` / `views/HomeView.ets` / `views/SettingsView.ets` 删 import 与调用（`refreshReminders()`、`askNotify()`、`doReschedule()`、`pickRemindTime()`、`clearReminders()`、5 个 `@State`）
- `store/Store.ets` 删 `remindTime` / `loadRemindTime()` / `setRemindTime()`
- `components/TaskSheet.ets` 与 `components/EventSheet.ets` 删「提醒」下拉项（`REMIND_KEYS`/`REMIND_LABELS`、`@State remind`、`remindIndex()`、`remind_min` 写入、提示行）
- 协议页、隐私弹窗、设置页文案全部同步

**但保留了铃铛。** 这是个重要区分：

| 能力 | v4.20 前 | v4.20 后 |
|---|---|---|
| 系统代理提醒（弹到 App 外面） | ✅ 用 `reminderAgentManager` | ❌ **删除** |
| 铃铛里的「提醒清单」 | ✅ 纯本地 SQL 算 | ✅ **保留** |

铃铛里的清单是 `db/Repo.ets` 的 `static async reminders()` 查出来的（逾期 / 今天到期 / 12 小时内要做），纯本地计算，零权限也照样能用。DB 的 `remind_min` 列和 `api/Types.ets` 的字段也保留不动，老数据里的「提前 5 分钟」仍能体现。

**副作用**：铃铛标题从「提醒」改成「提醒清单」，避免用户以为它会发系统通知。

### 1.5 第四次微调：配色方案的反转（v4.21 → v4.22）

这是唯一一次**「技术上正确但视觉上被否」**的决策，值得完整记下来。

v4.21 处理 AGC 的「色彩对比度不达标」时，遇到一个两难：

- App 里有 35 处**白字压在亮色填充上**（品牌青绿、渐变按钮），实测对比度全部只有 1.6–3.3
- 两条路：①把填充压深保白字 ②填充不动、字改深色

我第一版选了 ②，理由是「把 `brand` 压到 4.6:1 会让青色发闷、与网页版差太远」。技术上完全成立 —— 实测深墨绿 `#04211F` 压在所有填充上都是 6.27–10.4，全过。

结果你看到了截图，直接否掉：

> 「你把浅色模式下的绿色标签下的字体颜色都改成黑色了，不能用白色吗，不然很难看，你直接回答我行不行就行了」[m28666]

我回答「可以」，给了两条路，你回「1」= ①压深填充保白字。

### 3.2 命令行构建（固定三件套）

```bash
cd /Users/hina/DevEcoStudioProjects/workbench

# ① 必须先删字节码产物
rm -f entry/build/default/intermediates/loader_out/default/ets/modules.abc

# ② 三个环境变量必须设
export NODE_HOME=/Applications/DevEco-Studio.app/Contents/tools/node

export DEVECO_SDK_HOME=/Applications/DevEco-Studio.app/Contents/sdk

# ③ 构建
node "/Applications/DevEco-Studio.app/Contents/tools/hvigor/bin/hvigorw.js" \
  assembleHap --mode module -p product=default -p buildMode=debug --no-daemon
```

| 变量缺失 | 报错 |
|---|---|
| `DEVECO_SDK_HOME` | `ERROR: 00303217 Configuration Error` |
| `JAVA_HOME` | `Error Code: 00308018 Unknown Error` + `Unable to locate a Java Runtime.` |

`--no-daemon` 必加。

#### 3.2.1 最重要的一条：必须删 `modules.abc`

**不删这一步，`BUILD SUCCESSFUL` 是骗人的。**

hvigor 的 `CompileArkTS` 只沿 `main_pages.json` 里注册的页面追 import。**孤儿 `.ets` 文件根本不进编译图** —— 你新加一个文件，它不存在任何 import 链上，编译会「成功」，但里面所有语法错误都不会被发现。

判断方法：编译成功后 grep 产物字节码里有没有你新加的符号。

```bash
# 验证符号真的进了编译图
grep -c "你的新函数名" entry/build/default/intermediates/loader_out/default/ets/modules.abc
```

> 这个坑在项目里至少踩了两次（v2.2 加 `AiView`、v4.3 改 `Chart`）。**结论：每次编译前都删。**

#### 3.2.2 CLI 0 ERROR ≠ IDE 0 ERROR

`ArkTSCheck` 是另一套检查器。CLI 编译通过不代表 IDE 的 Problems 面板干净。

**交付前必须让你在 IDE 里看一眼 Problems 面板。** 这个提醒在 v2.x 就写进文档了，至今有效。

### 3.3 release 出包（商店要 `.app` 不是 `.hap`）

```bash
# ① 临时把签名切到 release
#    build-profile.json5 的 products[0].signingConfig: "default" → "release"

# ② 出包
node ".../hvigorw.js" assembleApp --mode project \
  -p product=default -p buildMode=release --no-daemon

# ③ 立刻切回 default（否则 hdc 装不上）
```

#### 4.3.4 致命 bug：`last_insert_rowid()` 跨连接

**v4.0 上线后第一个真机致命 bug。**

`Db.insert` 原本这样拿新行 id：

```sql
SELECT last_insert_rowid() AS id
```

问题：**RDB 的 `executeSql` 与 `querySql` 可能落在连接池的**不同连接**上**，于是 `last_insert_rowid()` 返回 0。**

现象：`getTask(0)` 查不到刚插入的任务 ⇒ 抛「任务创建失败」—— **但行其实已经入库了**。用户看到「添加失败」，刷新一下又出现了。

修法（`Db.insert(sql, args, table)` 多收一个表名）：

```typescript
let id = 0;
// ... executeSql 之后
if (id <= 0) {
  // 主键都是 INTEGER PRIMARY KEY AUTOINCREMENT，单机单用户 MAX(id) 就是新行
  id = await this.queryOne(`SELECT MAX(id) AS id FROM ${table}`);
}
```

`Repo` 里 6 处调用补上了表名。

#### 4.3.5 事务与导入导出

**v4.0 就有，v4.4 加固。**

`Db.beginTx()` / `commitTx()` / `rollbackTx()`（同步 void，各自 try/catch）。

`importJson` 的流程（**先校验，再清空**）：

```
1. 校验：JSON 合法？data.app === 'personal-workbench-harmony'？五个数组都是 Array？total > 0？
2. BEGIN
3. clearAll()
4. 逐类插入
5. 恢复 user_name
6. COMMIT
   catch → ROLLBACK，抛「恢复失败，原数据没有动」
```

**关键点：校验在事务外、清空在事务内。** 校验不过就完全不碰原数据。

### 5.5 通用卡片（`components/Card.ets`）—— v4.11 的关键改造

**问题**（你贴的平板截图 [m19161]）：

> 「每一个板块之间肯定还是是有空隙的…你看本周成长趋势和模块投入占比都靠在一起了，然后最近任务和核心模块上下又空太多」

**根因是两条，都不是「间距设小了」**：

**根因 A（横向贴太近）**：

```typescript
R.span2() = '67.5%'   // + R.span1() = '31.5%' = 99%
```

Flex `justifyContent: FlexAlign.Start` ⇒ 剩余的 1% 全堆到行末，**两块之间 0 间距**。

**根因 B（纵向大空当）**：

Flex `alignItems: ItemAlign.Stretch` **只拉伸「未设尺寸」的子项** ⇒ 被拉伸的是**外层包裹 Column**，里面的 Card 根 Column 没有 height ⇒ 卡片白底不撑满，行高被高卡片撑起后矮卡片下方留白。

**修法**：

```typescript
// Card.ets
@Prop fillHeight: boolean = false;

@Builder cardInner() { /* 头部 Row + body Column */ }

build() {
  if (this.fillHeight) {
    Column() {
      this.cardInner()
    }
    .width('100%').height('100%')      // ← 关键
    .backgroundColor(...).borderRadius(...)
  } else {
    Column() { this.cardInner() }.width('100%')
  }
}

// HomeView.ets
.layoutWeight(this.gw(2))               // 宽屏给权重
.margin({ top: S.gapLg, right: this.gapHalf() })
// gapHalf(): 宽屏 7, 窄屏 0
// Card 调用加：fillHeight: this.gridWide()
```

> **`GridRow`/`GridCol` 救不了这个**：它们解决的是「列宽分配」，解决不了「子项不设高度就不被拉伸」。

AGC 第一次提审被打回，给了三条：两个隐私弹窗、平板加不了任务、清空数据后数字不刷新。三条根因各不相同，值得记：

### 5.13 平板竖屏：布局与弹层（v4.26）

**用户原话（m31090）**：「我刚切到平板的竖屏模式了，首页的布局出问题了，然后其他页面的弹窗以及弹窗遮罩也出问题了。」
设备：MatePad Pro 13 模拟器**竖屏** 1920×2880 px / 960×1440 vp / density 2（模拟器无法程序化旋转，只能测当前方向）。

| 现象 | 根因 | 修法 |
|---|---|---|
| 内容区被挤成窄列、KPI 变 2 列、卡片大片留白、最后一张卡被挤没 | ①`R.update()` 按窗口宽度定档，竖屏 960vp 仍算宽屏、侧栏照旧占 224vp（网页端 ≤980px 会收成 70vp 图标栏）②2 列时宽卡仍 span=2 ⇒ 宽卡独占整行、窄卡半行，而 **ArkUI 的 GridRow 不会像 CSS grid 自动补位** | `R.railCompact()`（宽屏但 <980vp ⇒ 侧栏 70vp）+ `SideRail` 的 compact 分支；KPI 加 620–900vp 档（3+2 两行，卡片 `.layoutWeight(1)`）；`spanFor()` 改成「只有 3 列时宽卡才占 2 列」；`gridWide()` 放宽到 2 列也做同行等高 |
| 弹窗卡片超出屏幕底部（底部「取消/保存」整行被切掉）、遮罩只盖住下半屏 | **`bindSheet` 的面板高度是平台按「内容高度」算的**，`height`（`'100%'`/数值/`SheetSize.LARGE`）与 `preferType: SheetType.POPUP` 实测都不生效；面板永远贴底、内容被裁 ⇒ 自己画的遮罩最多盖住面板那一块 | **宽屏彻底不用 bindSheet**：视图 build() 根节点包一层 `Stack`，弹层作为**普通子组件**渲染（`if (wideMode && wideOpen) { sheetBuilder() }`），遮罩与居中卡片由 `SheetFrame` 宽屏分支自己画；窄屏照旧走底部抽屉 |

顺带记两条同源的小坑：`.overlay()` 属性当浮层用会**不刷新并吃掉点击**（点击被 `Refresh` 的 `PanRecognizer` 抢走）；

**隐私托管的结论**：你已在 AGC 开通并配好「隐私声明托管服务」⇒ **平台会自动弹标准隐私弹框，App 侧不用调任何接口**。
`privacyManager` 属于 `@kit.AppGalleryKit`（华为应用市场 HMS），只在带 HMS 的华为手机上有；纯 OpenHarmony 7.0 没有这个模块，
静态 import 会直接崩 ⇒ 本项目（目标就是纯血鸿蒙）**不接这个接口**，只要保证不再自己弹一次（v4.25 已删自建隐私门）。

### 5.11 边界反馈动效（v4.24）

**用户原话（m30044）**：「界面滑动到边界位置时 (上下滑动到顶部或底部，左右滑动到左边界或右边界)，应该有反馈动效。」

**根因**：`Scroll` 的 `edgeEffect` 默认是 `EdgeEffect.None`（SDK `common.d.ts:25291`：只有 `List` 默认 `Spring`），
本工程 17 处 `Scroll` 里 6 处漏配 ⇒ 滑到顶/底是硬停。

**做了三件事**：

1. **回弹**：6 处漏配的补 `.edgeEffect(EdgeEffect.Spring)`，17 处现在全部有。
2. **判定**：`onWillScroll` 的 `scrollSource === ScrollSource.EDGE_EFFECT` 才是「真的拉出边界」；
   `onScrollEdge((side: Edge))` 给方向（`Edge` 只有 Top/Bottom/Start/End，没有 Left/Right）。
3. **提示**：新建 `utils/EdgeHint.ets` + `components/EdgeHint.ets`，AppStorage + `@StorageLink` + `@Watch` 驱动，
   文案「已经到顶了 / 已经到底了 / 已经到最左边了 / 已经到最右边了」，
   淡入淡出用 `getUIContext().animateTo`（`.transition()` 不可靠），挂在 `pages/Index.ets` 根 Stack 顶层。

**验证**：模拟器上首页滚到底 ⇒ 日志有 `edge overscroll`、出现「已经到底了」；
任务面板页顶部越界 ⇒ 出现「已经到顶了」；点底部导航仍能切页（overlay 不吞触摸）。

**一处如实说明**：首页顶部往下拉是**下拉刷新**（`views/HomeView.ets:1061` 的 `Refresh` 包着 `Scroll`），
所以首页顶部**不会出现**「已经到顶了」——那是两套手势在抢，首页有更明确的下拉刷新反馈。
另外本工程**没有横向滚动容器**，「最左/最右」的文案备好了但暂时用不上。

#### 6.2.4 一个反直觉的事实：解包会丢签名块

**用 `unzip` 解出来的 hap 没有签名块 ≠ 没签名。**

签名块不是 zip entry，而是**插在 central directory 之前的裸数据**，magic 是 ASCII `<hap sign block>`（hex `3c686170207369676e20626f636b3e`）。

正确判定必须解析 raw 字节：

```
找 zip central directory → 算 local header 偏移 → 看数据尾到 cd_off 之间的块
```

实测：

| 对象 | 有签名块？ |
|---|---|
| `小记-v1.0.0-release.app` | ✅ 有 |
| 内层 `entry-default.hap` | ❌ 无 |

**内层无签名是 hvigor `PackageApp` 的正常行为** —— 它打的是 unsigned hap，签名做在 `.app` 容器上（日志 `no need to sign code for :app`）。SDK 官方校验器也放行。

根因不是「漏改了」，而是**根本不是这么量的**。

**根因**：`fontSize` 是字体框，框里画出来的**墨迹**可以小得多。

**落盘**：

| # | 事项 | 做法 |
|---|---|---|
| 1 | 换符号 | `components/Icon.ets` 的 `sym()`：`left→arrow_left`、`right→arrow_right`、`down→arrow_down`、`up→arrow_up` |
| 2 | 字号 | 独立按钮里的箭头 fs16，行内箭头 fs14；其余 28 处 fs12 统一抬 fs14（15 个文件） |
| 3 | 字符伪图标 | `Text('⋯')`（墨迹 11.1×**2.3**vp）→ `sym('more')`；`Text('•')`（墨迹 **3.4×3.4**vp）→ `sym('bullet')`（`Icon.ets` 新增 case → `circle_fill`） |
| 4 | 容器同步放大 | `TasksView` 15→18、`ProjectsView` 13→16、`EventSheet` 15→18；`StatusDot` 勾比例 `dotSize*0.6→0.7` |
| 5 | 工程卫生 | 删临时校准页 `pages/IconCal.ets`、还原 `EntryAbility.ets:130` 与 `main_pages.json`、移出 4 个 `.bak_v413` |

**实测结果（12 页、193 个图标节点）**：

| 口径 | 结果 |
|---|---|
| 盒子最小边 | 13.1 / 14.0 / 15.1 / 16.0 / 17.1 / 19.7 / 28.0 / 30.0 ⇒ **< 8vp = 0、< 12vp = 0** |

**教训**：图标尺寸这事，**别信 `fontSize`，信像素**。窄字形只能换符号，放大字号是死路。

### 8.1 工具链类（6 条）

#### 坑 1 · CLI `BUILD SUCCESSFUL` 不代表新文件被检查过

**现象**：新加一个 `.ets` 文件，编译通过，但文件里写错了语法也不报错。

**根因**：hvigor 的 `CompileArkTS` 只沿 `main_pages.json` 注册的页面追 import。**孤儿 `.ets` 不进编译图。**

**修法**：

```bash
rm -f entry/build/default/intermediates/loader_out/default/ets/modules.abc
```

**验证**：grep 产物字节码里的新符号。

**代价**：至少踩了两次（v2.2 加 `AiView`、v4.3 改图表）。

#### 坑 2 · CLI 0 ERROR ≠ IDE 0 ERROR

**现象**：命令行编译干净，IDE 的 Problems 面板有红。

**根因**：`ArkTSCheck` 是另一套检查器。

**修法**：交付前必须让你看 IDE 的 Problems 面板。

#### 坑 3 · 三个环境变量少一个就报不同的错

| 缺失 | 报错 |
|---|---|
| `DEVECO_SDK_HOME` | `ERROR: 00303217 Configuration Error` |
| `JAVA_HOME` | `Error Code: 00308018 Unknown Error` + `Unable to locate a Java Runtime.` |

**根因**：DevEco 自带 JBR 25.0.2；系统 `/usr/bin/java` 是 macOS 占位空壳。

**修法**：三个变量 + `--no-daemon` 一起用。

#### 坑 4 · 同包名不同证书装不上

**现象**：`hdc install -r` → `code:9568332 error: install sign info inconsistent.`

**根因**：同包名不同证书签名。

**修法**：

```bash
hdc uninstall com.lbuding.workbench   # 先卸
hdc install ...                        # 再装
```

#### 坑 5 · 模拟器 hdc 通道会坏

**现象**：`install` 卡死、`hdc list targets` 返回 `[Empty]`。

**修法**：`Emulator -stop` + pkill + 重启模拟器。

> 另一条：模拟器实例启动后端口会漂（先起 `Mate 70 Pro` 报 5557，随后 `[Empty]`），重启一次才稳定在 5555。

#### 坑 6 · `app_check_tool.jar` 少参数就报 `code:9132105`

**现象**：`ScanVerify commandVerify stat parameter is null`。

**修法**：必须带 `--stat-duplicate true --stat-suffix true --stat-file-size 0`。

### 8.2 ArkTS 语言限制类（7 条）

#### 坑 7 · 对象字面量不能直接当泛型返回

**报错**：

```
10605038 ArkTS Compiler Error
Object literal must correspond to some explicitly declared class or interface
(arkts-no-untyped-obj-literals)
At File: api/Http.ets:153:14
```

**修法**：

```typescript
// ❌ return {} as T;
// ✅
return JSON.parse('{}') as T;
```

#### 坑 8 · `throw e` 触发 `arkts-limited-throw`

**修法**：

```typescript
const err: ApiError = e as ApiError;
throw err;
```

#### 坑 9 · `@Component` 内方法名不能叫 `create`

**根因**：`create` 是 ArkTS 保留字。

**修法**：`NotesView.create()` → `NotesView.createNote()`。

#### 坑 10 · 组件属性名不能撞基类方法名

**现象**：报错提到 `padding` / `size`。

**根因**：`Card` 继承 `CustomComponent`，基类已有同名方法。

**修法**：`Card` 不能有名为 `padding`/`size` 的 `@Prop`。

#### 坑 11 · `Text(方法)` 会传函数对象

**现象**：显示成 `[function]`。

**修法**：包一层 `@State`，UI 里读 `@State`。

#### 坑 12 · 一个 `@BuilderParam` 只能有一个

**报错**：`10905102`。

#### 坑 13 · `$$this.x` 在 `@BuilderParam` 尾随闭包里不回写

**现象**：输入框里能打字，但保存后拿到的是空值。

**根因**：ArkUI 的 `$$` 双向绑定在 `@BuilderParam` 的尾随闭包作用域里不生效。

**修法**：改成显式 `.onChange`：

```typescript
// ❌
TextInput({ text: $$this.title })
// ✅
TextInput({ text: this.title }).onChange((v: string) => { this.title = v; })
```

**踩了两次**：v2.3（TaskSheet 4 处 / EventSheet 3 处 / AiView 1 处 = 8 处）、v4.2（`$$this.x` 又出现在 8 处）。

### 8.3 ArkUI 布局与更新类（12 条）

#### 坑 14 · ArkUI V1 精准更新：方法调用里读 state 不算依赖

**现象**：保存后界面不刷新，切标签才刷新。

**根因**：只有「属性表达式里直接读过 state 变量」的节点才重画。

```typescript

// ✅ 预计算进 @State
@State gTodo: number = 0;
```

**踩了三次**：v2.7（ForEach key）、v4.2（三列计数）、v4.5（12 个 view 全量）。

**现象**：页面内容垂直居中，顶部一大块空白。

**修法**：13 个文件 14 处补 `.align(Alignment.TopStart)`。

> **不要动 33 处 `justifyContent(FlexAlign.Center)`** —— 那是小控件内部居中。

**现象**：日程条被拉到全屏高。

**根因**：`height('100%')` 在「高度由内容决定」的容器里，冒泡到最近有确定高度的祖先。

**现象**：`GridRow`/`GridCol` 也救不了坑 16。

**修法**：`onAreaChange` 量高度 + 回填**具体数字**。

**修法**：key 追加 `-${this.tick}`（11 个 view 全量改）。

**现象**：同行卡片不等高，矮卡下方留白。

**修法**：`Card` 加 `@Prop fillHeight` + 根 Column `.height('100%')` + `.layoutWeight()`。

**修法**：改用 `.layoutWeight()` + `.margin()`。

**文档 v2.7 之前写反成「24 < 20 不可用」**，已更正。

**探针实测**：`density=3.5`、`sysBottom=0`、`gestBottom=0`、`indBottom=98`。

**现象**：`SideRail.active` 高亮永远停在第一项。

#### 坑 25 · 自定义组件后不能另起一行挂 `.width()`

**修法**：包进 `Column()`。

#### 坑 26 · `SheetOptions` 里根本没有 `onDisappear`

**成员全集**（实测）：`height/dragBar/maskColor/detents/blurStyle/showClose/preferType/title/shouldDismiss/onWillDismiss/onWillSpringBackWhenDismiss/enableOutsideInteractive/width/borderWidth/borderColor/borderStyle/shadow/onHeightDidChange/mode/scrollSizeMode/onDetentsDidChange/onWidthDidChange/onTypeDidChange/uiContext/keyboardAvoidMode/enableHoverMode/hoverModeArea/effectEdge/radius/detentSelection/placement/placementOnTarget/showInSubWindow/enableFloatingDragBar/modalTransition/radiusRenderStrategy/systemMaterial`

#### 坑 54：`bindSheet` 的面板高度是「内容高度」，`height`/`preferType` 都改不动它（v4.26 踩到）

平板竖屏上弹层被裁、遮罩只盖半屏，根因是**平台行为**不是代码写错：面板高度由内容高度决定，
`SheetOptions.height`（`'100%'` / 数值 / `SheetSize.LARGE`）与 `preferType: SheetType.POPUP` 实测**都不生效**
（竖屏实测面板恒 560vp、永远贴底、内容被裁），自己画的遮罩最多只能盖住面板那一块。
**正解**：宽屏改成**在页面里自己画浮层** —— 视图的 build() 根节点包一层 `Stack`，弹层作为普通子组件渲染，
遮罩与居中卡片由 `SheetFrame` 宽屏分支负责；窄屏照旧用 bindSheet 底部抽屉。
附带：`.overlay()` 属性不能当浮层（不刷新 + 吃掉点击）；ArkUI 的 GridRow 不会像 CSS grid 自动补位。

### 8.5 数据与存储类（5 条）

#### 坑 32 · `last_insert_rowid()` 跨连接返回 0（致命）

**现象**：添加任务报「任务创建失败」，但刷新一下又出现了。

**根因**：RDB 的 `executeSql` 与 `querySql` 可能落在**连接池的不同连接**上。

**修法**：`Db.insert(sql, args, table)` 多收表名，≤0 时退回 `SELECT MAX(id) AS id FROM <table>`。

#### 坑 33 · 禁止 `toISOString()`

**现象**：时间差 8 小时。

**修法**：本地墙上时间 `yyyy-MM-ddTHH:mm`，`Db.now()`。

#### 坑 34 · `isOverdue` 不能用 `D.parse` 比较

**现象**：无到期日的任务被算成逾期 7000+ 天。

**根因**：`D.parse('')` 被解析成 1899 年。

**修法**：字符串比较 `t.due_date.slice(0,10) < D.today()`。

**修法**：校验在事务外，清空在事务内，失败 ROLLBACK 并抛「恢复失败，原数据没有动」。

#### 坑 36 · `clearAll()` 要先置 `initialized` 标记

否则用户清空后重启会被重新铺一遍种子。

### 8.8 上架与合规类（3 条）

#### 坑 45 · AGC 上架测试会拿对比度和图标 12vp 卡你

**三个易漏点**：

1. **对比度要按最差底色算**，不能只对白卡算 —— App 里有 24 种真实底色
2. **白字压彩底必挂，但别压暗品牌色** —— v4.21 先走了「压深字」被否，v4.22 改「压深填充」
3. **`caretColor` 不算文字色**

**应用图标内间距判据**：

```python
fg.getchannel('A').getbbox()   # 应接近 (0,0,1024,1024)
```

#### 坑 46 · `read` 工具显示多行文件时会错位/吞字符

**现象**：`read` 显示 `this.startAt = e.start_at79:`（实际文件完好）。

**修法**：怀疑损坏时用 `od -c` / `awk | od -c` 验原始字节。

#### 坑 47 · AGC 量的是「渲染出来的墨迹」，不是 `fontSize`

**现象**：v4.21 已把 30 处 `<12vp` 的 `SymbolGlyph` 统一抬到 12vp，AGC 第二轮**仍报同一条**「图标 6 次不通过」。

**根因**：`fontSize` 是**字体框**，框里画出来的图形（墨迹）可以小得多。
`chevron_right` 在 `fontSize(12)` 时**盒子宽度只有 6.3vp**、墨迹 4.3×6.9vp；
拉到 `fontSize(24)` 盒子 12.3、墨迹 6.9×12.9 —— **宽向永远过不了 8vp 硬底线**。
而 AGC 报的「6 次」正好等于工程里 `chevron` 窄箭头的用法数（`right`×4 + `left`×1 + `down`×1，另有 4 处经参数传入）。

**修法**：**换符号，不是放大字号**。实测后换成 `arrow_right`/`arrow_left`/`arrow_down`/`arrow_up`：

| 符号 | fs | 盒子 | 墨迹 |
|---|---|---|---|
| `chevron_right`（旧） | 12 | 6.3×12.0 | 4.3×6.9 ✗ |
| `arrow_right`（新） | 16 | 16×16 | **14.3×12.0** ✓ |
| `arrow_left`（新） | 16 | 16×16 | **12.0×12.0** ✓ |
| `arrow_down`（新） | 16 | 16×16 | **12.0×13.1** ✓ |

**怎么量（可复用）**：`uitest dumpLayout` 拿节点 bounds → `snapshot_display` 截图 →
在框外扩 7–10px 取四角众数当背景色 → 统计色差 >60 的像素求墨迹 bbox → **px ÷ density(3.5) = vp**。

**附带两条**：

- `SymbolGlyph` **不能从 `@kit.ArkUI` import**（它是全局组件）；`$r('sys.symbol.xxx')` **必须是字面量**
  ⇒ 加新符号只能在 `components/Icon.ets` 的 `sym()` switch 里加 case。
- 符号名**能不能用，查 SDK 源码不可靠**（`sysResource.js` 有 3847 个名字，编译仍可能报 `Unknown resource name`），
  **以编译结果为准**。

**代价**：花掉一整轮往返，但换来了「怎么自己量」的通用方法。

---

#### 坑 48 · 全屏 overlay 吞掉所有触摸 —— `hitTestBehavior` 要写在自定义组件的**使用处**

v4.24 的边界提示是一个全屏 `EdgeHint({})` 挂根 `Stack`，`.hitTestBehavior(HitTestMode.None)` 写在组件内部 ⇒
**模拟器上所有点击全部失效**（隐私弹窗按钮点不动、协议链接点不动、swipe 1px 都无效）。
原因：ArkUI 的命中测试节点是**自定义组件的使用处**，组件内部根节点的 `None` 管不到外层。
修法：`None` 写到使用处、去掉 `zIndex`。排查手法：注释掉 overlay 重建，点击立刻恢复即可确认。

#### 坑 49 · 淡入淡出别用 `.transition()`；短命 UI 抓不到就调长时长

- `.transition(TransitionEffect.OPACITY...)` 时序不稳 ⇒ 改 `@State` + `getUIContext().animateTo({duration}, cb)`。
- API 26 上 `animateTo` 已 deprecated，旧签名 `animateTo(160, cb)` 会报 `10505001 ArkTS Compiler Error`。
- `@Entry @Component` 的 `build()` 只能有一个根节点，写语句会报 `10905210`。
- `dumpLayout` + `snapshot_display` 一个来回 > 1 秒，胶囊显示 1.6 秒时**永远 grep 不到** ⇒ 测试时先把时长改成 4000ms。
- `hilog.debug` 默认被过滤，排查要改 `hilog.info`。

#### 坑 50 · `Refresh` 吃掉顶部下拉手势，所以首页顶部没有「已经到顶了」

`views/HomeView.ets:1061` 的 `Scroll` 被 `Refresh` 包着（全工程唯一一处），顶部往下的手势被下拉刷新接走。
另外**手势方向老搞反**：手指往上拖＝向下滚，往下拖＝向上滚。

---

#### 坑 51 · 平台接管隐私声明后，自制的首启同意页必须删掉

AGC 审核原话：「应用出现两个隐私弹窗…您已接入平台隐私托管服务，建议您删除自行构建的隐私声明弹窗」。
平台先弹一次系统隐私声明，我们再弹一次自制的 ⇒ 用户看到两个弹窗，直接判不通过。
**处理**：删 `components/PrivacyDialog.ets` + `utils/Privacy.ets` + `pages/Index.ets` 的隐私门分支 + `EntryAbility.ets` 的初始化；
**保留 App 内协议查看页**。

#### 坑 52 · 算「窗口高度」别用「屏幕高度」

平板横屏/分屏时**窗口比屏幕矮** ⇒ 用屏幕高度算出来的抽屉比窗口高 ⇒ 底部固定条（保存/取消）被挤出屏幕 ⇒「加不了任务」。
正解：根节点 `.onAreaChange` 拿窗口实际尺寸喂给 `R.update()`。
另外 `SheetFrame` 宽屏分支原本**多包了一层 Scroll**，与内容自己的 Scroll 嵌套 ⇒ 外层抢手势却滚不动 ⇒ **宽屏分支不要自己再包一层 Scroll**。

#### 坑 53 · ArkUI V1 的 `@Builder` 参数是「按值传」—— 数字必须写在 builder 内部

审核原话：「清空全部数据后，设置页面的数据未被清空，切换页面才更新」。
**内存里已经是空数组了，界面还是旧数字** —— 因为 `${this.tasks.length}` 是在父组件 build() 时算好的字符串，
builder 自己没有对 `this.tasks` 的依赖 ⇒ 不重画。
**只把数字预计算进 `@State` 是不够的**（试过，照样不刷新）—— **必须让 builder 内部直接读到 state**
（`views/TasksView.ets` 的 `tstat` 就是这么写的，所以它能实时刷新）。

## 结语

这个项目从「把一个网页版搬到手机上」开始，走了 22 个版本，最后落在两个很朴素的结论上：

1. **数据在用户自己手里。** 不联网、不注册、不申请任何系统权限 —— 这不是妥协，是用户明确要的东西，也是这个 App 唯一的隐私承诺。

2. **合规和好看可以兼得，但要先算。** AGC 说对比度不足 4.5:1，人眼完全看不出来，是脚本算出来的；同样，压深填充后主色深了一档，是用户一眼就看出来的。**该算的用脚本算，该看的给人看。**

中间踩的 46 个坑，绝大多数不是「我不会」，是「ArkUI/ArkTS 的行为和直觉不一样」。这些都记在第 8 章了 —— 将来谁接手这个工程，希望不用再踩第二遍。

至于还在等的那张 AGC 审核回执，等就是了。
